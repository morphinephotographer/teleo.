# teleo. — диагноз и исправление подключения телефона

## Подтверждённая причина локальной недоступности

Исходный `npm run dev` запускает Vite с `--host 127.0.0.1`; `RemoteLink.host()` создавал приглашение из `location.origin`. Поэтому студия по `http://127.0.0.1:5173` выдавала телефону тот же loopback URL. Сетевой listener проверен: Vite действительно был доступен только на 127.0.0.1:5173. На iPhone этот адрес относится к самому телефону и не достигает Mac. Это подтверждённая ошибка конфигурации данного локального пути, а не предположение о поломке production relay. Физические настройки Wi-Fi/изоляции/брандмауэра конкретного iPhone не проверены.

Простая замена host на 0.0.0.0 недостаточна: Safari на обычном HTTP LAN не получает необходимый secure context для Web Crypto, а relay разрешает только точные Origin. Подмена URL на public staging также не соединяет две независимые комнаты relay и не переносит локальную библиотеку.

## Изменения

- На loopback больше нет QR, предлагающего заведомо недоступный телефону адрес. Остаётся явно обозначенная ссылка для двух браузерных контекстов на этом Mac.
- HTTP вне secure context показывает понятное требование HTTPS до инициализации Web Crypto; обход проверки сертификатов не предлагается.
- Приглашение использует фактический origin/порт и поддерживаемый `lang` хоста. Токен остаётся во fragment и очищается из адресной строки при принятии.
- Ошибка недоступности сети `serverUnreachable` отделена от `expired` и от потери уже разрешённой пары. Терминальные приглашения не перезапускаются автоматически. При временном разрыве разрешённой пары сохранены существующие bounded resume, ACK, target/replay и обновление состояния.
- UI истекает через 120 секунд, отменяет старый таймер по connected/revoke/renew и не показывает просроченный QR/link. Backend TTL, одноразовость, auth, согласие preview и rate limits не ослаблены.
- `npm run dev:lan` — отдельный явный opt-in. Требует частный IPv4 реального интерфейса Mac и сертификат/ключ. Vite привязывается только к указанному интерфейсу; relay остаётся на loopback, с изолированным `.wrangler/lan-state` и точным HTTPS Origin.
- В LAN используется HTTPS и между Vite и loopback relay; proxy проверяет сертификат через переданный CA/сертификат и servername. `secure:false`, wildcard CORS и переписывание Origin на доверенное значение не используются.

### Дополнительно найдено при реальном запуске

Первый вариант HTTPS Vite → HTTP Wrangler не проходил strict Origin: локальный runtime Wrangler переписывал входящий `https://LAN:port` в `http://LAN:port`. Сопоставлены только значения Origin, без логирования токенов/текста. Решение — HTTPS до loopback relay с проверкой сертификата, а не расширение allowlist на небезопасные или произвольные Origin. Vite CORS middleware также перехватывал OPTIONS; теперь API preflight доходит до exact-origin relay. Временные диагностические console-выводы удалены.

## Повторение LAN-запуска

Потребуется сертификат с SAN для фактического адреса Mac, доверенный **на Mac и iPhone**, его приватный ключ и при необходимости CA PEM. Не импортируйте временные QA-ключи, не обходите предупреждения Safari и не коммитьте ключи. Установка доверия на устройствах — ручная операция владельца. Apple Developer Team для браузерного пульта не нужна.

```sh
TELEO_LAN_HOST=192.168.1.20 \
TELEO_TLS_CERT=/absolute/private/server-cert.pem \
TELEO_TLS_KEY=/absolute/private/server-key.pem \
TELEO_TLS_CA=/absolute/private/issuer-ca.pem \
npm run dev:lan
```

Адрес — пример, замените его реальным IPv4 интерфейса. По умолчанию UI слушает 5183, отдельный relay — 18787; можно задать `TELEO_LAN_PORT`/`TELEO_RELAY_PORT`. Откройте выведенный HTTPS `/studio` **на Mac**, затем подключайте iPhone к той же достижимой сети. Библиотеки loopback/LAN/public — разные origins; переносить тексты следует явно через экспорт/импорт, без очистки данных.

```sh
TELEO_LAN_ORIGIN=https://192.168.1.20:5183 \
TELEO_TLS_CA=/absolute/private/issuer-ca.pem npm run check:lan

TELEO_LAN_ORIGIN=https://192.168.1.20:5183 \
TELEO_TLS_CA=/absolute/private/issuer-ca.pem npm run check:lan:pairing
```

Первый check проверяет TLS/route/proxy/точный Origin и отказ постороннему Origin. Второй создаёт одноразовую тестовую пару, проходит WSS auth/approval, command/ACK и revoke без вывода credentials. Он использует `ws` из установленного прямого dev-dependency Miniflare, не добавляет runtime-зависимость веб-приложению.

## Фактически проверено

На реальном частном интерфейсе этого Mac запущен HTTPS LAN-сервер с отдельным однодневным QA-сертификатом. Node-клиенты доверяли ему явно через `ca`, с проверкой имени; системное/браузерное доверие и keychain не менялись. Проверены HTTPS studio, разрешённый preflight, 403 для постороннего Origin и настоящая WSS-пара: auth, явное approval, play-команда, точный ACK/state, revoke. Оба клиента работали на этом же Mac. Это **не** проверка физического iPhone и не доказательство отсутствия Wi-Fi client isolation.

## Ручная проверка на iPhone — НЕ ПРОЙДЕНА здесь

1. Доверить выбранный владельцем сертификат штатным способом на обоих устройствах; убедиться, что Safari не показывает предупреждение. Не отключать проверку TLS.
2. Открыть HTTPS LAN-адрес на телефоне вручную. При недоступности проверить одинаковую сеть, guest/client isolation, VPN, доступ входящих соединений и разрешение локальной сети. Настройки безопасности автоматически не менять.
3. Открыть студию на Mac по тому же origin, создать тестовый текст, получить свежий QR и отсканировать камерой iPhone в течение 120 секунд.
4. Подтвердить на Mac, проверить автоматическое закрытие QR, Play/Pause, countdown, скорость, seek/абзацы и двустороннее обновление типографики/отражения/фокуса.
5. Отдельно разрешить preview; проверить скрытие текста и отзыв согласия. Переключатель телефона не должен выдавать согласие от имени Mac.
6. Кратко прервать сеть и проверить resume; явно отозвать доступ — автоматического возврата быть не должно. Просроченный/использованный QR должен требовать новое приглашение.

Public staging/production в этой итерации не меняются. Для проверки там нужна отдельная разрешённая публикация текущей сборки; приватный dev-сервер не является production-решением.

Токен не печатался и не сохранялся в репозиторий; тестовая комната отозвана. Это не заменяет камеру iPhone. Временный LAN QA-сервер после проверки остановлен; исходные loopback dev/relay оставлены.
