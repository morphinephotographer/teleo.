# Аудит веб-клиента teleo. и исправление заставки Safari

Дата: 27 октября 2026. Исходная версия: `4f556ab`, ветка `codex/teleo-v06-approved-ui`. Перед работой дерево было чистым. Публикация, push и изменение production не выполняются.

## Проверенная область

Рендер заставки и CSS, жизненный цикл диалогов, очередь автосохранения и IndexedDB, удаление папок/сценариев, применение команд пульта, смена сценария, контроль поколения/сокета, схемы числовых метаданных, согласие на текст, origin/auth/ACK/replay/expiry и существующие регрессии. Нативные Apple-клиенты не изменены; это не отдельный аудит Swift/CloudKit или внешней инфраструктуры.

## Подтверждённые находки

### 1. P1 — удаление продолжалось после неудачного сохранения

`DraftWriter.flush()` намеренно сохраняет неудачные записи для повторной попытки и не отклоняет Promise. Вызовы удаления трактовали завершение этого Promise как успешную запись. При ошибке IndexedDB удаление папки могло продолжиться и перечитать старую версию текстов из базы. Удаление сценария предварительно ставило tombstone в обычную очередь: после ошибки и отмены операция могла повториться фоновым автосохранением.

Исправлено: добавлен `requireSaved()`, останавливающий зависимую операцию, пока остаются несохранённые черновики. Удаление папки выполняется после этого барьера. Tombstone сценария записывается явно и меняет библиотеку только после успешной транзакции; неудачное удаление не остаётся в фоновой очереди. На время операции блокируются конкурирующие изменения соответствующего сценария, а при удалении папки — изменения всех сценариев. Recovery и повторная попытка обычного сохранения сохраняются.

Проверка: реальные отказы `IDBObjectStore.put` с `QuotaExceededError` в отдельных тестовых профилях; сохранность последнего текста, остановка удаления, восстановление записи и повторная попытка; отдельно — отсутствие отложенного удаления после Cancel и перезагрузки. Unit-тест проверяет барьер и recovery.

Файлы: `apps/web/src/drafts.ts`, `apps/web/src/main.tsx`, `tests/drafts.test.ts`, `tests/e2e/audit.spec.ts`.

### 2. P2 — отложенный кадр типографики мог изменить playhead другого сценария

Поколение `target` проверялось перед применением настройки, но не после `requestAnimationFrame`. Между этими шагами можно было сменить сценарий или сокет. Старый callback пересчитывал позицию уже нового текста по доле прокрутки прежнего.

Исправлено: перед отложенным изменением DOM/позиции повторно проверяются текущие `target` и сокет. Устаревший callback не перемещает новый сценарий; возврат состояния использует существующий защищённый канал.

Проверка: браузерный тест удерживает очередь RAF, применяет настройку к сценарию A, переключает на B с сохранённой позицией 200, затем отпускает кадры. Позиция B остаётся 200. Проверено на Chromium и WebKit.

Файлы: `apps/web/src/main.tsx`, `tests/e2e/audit.spec.ts`.

### 3. P2 — итоговый логотип зависел от посимвольных слоёв анимации

Ранее каждый символ имел исходную прозрачность 0, отдельные transform/filter-анимации и `forwards`. Независимой итоговой надписи не было. Пользователь сообщил, что Safari оставляет только первую букву. В изолированной пробе настоящего Safari полная надпись также не появилась; точный механизм композитинга не инструментирован. Установленный Safari — **27.0.1** (локальный Info.plist). Playwright WebKit **27.2** исходную потерю глифов не воспроизвёл, поэтому это не объявляется общим дефектом всех версий WebKit.

Исправлено: сборка букв стала декоративным слоем. Через 2100 мс компонент показывает обычный цельный текст `teleo.` и удаляет посимвольный слой. Видимость конечного текста не зависит от CSS animation, filter или `animation-fill-mode`. Сохранены Skip, reduced motion, завершение заставки через 3450 мс и однократный показ в сеансе. Персональные вкладки и библиотека пользователя не редактировались.

Проверка: EN/UK/RU, принудительно отключённые CSS-анимации, видимость полного текста, удаление сборочного слоя, автоматическое закрытие и отсутствие повтора после reload; чистые скриншоты Chromium/WebKit. Для нативной визуальной проверки предусмотрена dev-only проба `apps/web/__audit__/intro.html`, использующая настоящий компонент и удерживающая заставку после анимации. В production-сборку эта HTML-страница не входит.

После ручной разблокировки Mac пользователем повторная проверка исправления в **самом Safari 27.0.1 завершена**: в изолированной dev-пробе после reload визуально видно полное `teleo.`. В новой тестовой вкладке обычный `/studio?lang=ru` показал заставку и автоматически открыл студию; после reload заставка не повторилась. Обе созданные диагностические вкладки закрыты, исходные вкладки сохранены. Полные снимки окна с личными заголовками вкладок в репозиторий не сохранялись.

Файлы: `apps/web/src/Intro.tsx`, `apps/web/src/style.css`, `tests/e2e/audit.spec.ts`, `playwright.audit.config.ts`.

### 4. P2 — пустая студия явно выводила сокращение `t.`

Проверка основного экрана в настоящем Safari обнаружила отдельный от заставки wordmark: JSX `.empty-mark` содержал буквальный текст `t.`. Здесь остальные буквы не обрезались браузером — они отсутствовали в исходном тексте. Заменено на полное `teleo.`. Проверка Safari после reload визуально подтвердила все буквы. Это уточняет первоначальный диагноз: сообщение пользователя могло относиться к пустой студии, а не к анимации заставки.

В существующие проверки EN/UK/RU добавлены видимость и полный текст этой надписи после заставки. На мобильном экране тест закрывает библиотеку, чтобы открыть штатно скрытый за ней пустой экран. Чистые снимки тестовых профилей сохраняются как `audit-*-empty-logo.png`.

Файлы: `apps/web/src/main.tsx`, `tests/e2e/audit.spec.ts`.

## Проверки и доказательства

Финальные результаты: полный браузерный набор desktop/mobile Chromium — **114/114 PASS**, 2.1 мин; адресные Chromium/WebKit проверки — **12/12 PASS**; адресные unit-наборы — **27/27 PASS**; полный unit/relay — **71/71 PASS**, 152.62 с. `npm run lint`, `npm run typecheck`, `npm run build` и `npm run staging:check` завершились успешно. Последняя команда проверяет staging-сборку через `--dry-run`, публикации не делает. Первоначальный полный прогон дал 112/114: два новых теста не открывали библиотеку на мобильном экране. Их переходы адаптированы к существующему UI; проверки сохранности данных и гонки не ослаблены.

Скриншоты `docs/screenshots/audit-*-intro.png` получены из изолированных профилей, содержат целое слово и не включают пользовательские вкладки Safari. Визуально просмотрены итоговые RU-скриншоты desktop WebKit и mobile Chromium: вся надпись и кнопка видны, обрезания нет. Примеры: [desktop WebKit](../screenshots/audit-audit-webkit-ru-intro.png), [mobile Chromium](../screenshots/audit-mobile-ru-intro.png). Старые скриншоты v0.6 сохраняются. Полный веб-аудит не означает физическую проверку iPhone, Taptic, Bluetooth или VoiceOver.

## Ограничения

- Ручная проверка Safari 27.0.1 завершена после разблокировки Mac; настройки безопасности браузера не менялись.
- Публичный HTTPS/WSS и staging этой итерацией не изменялись и не публиковались.
- Проверки IndexedDB выполнялись только в автоматически созданных тестовых библиотеках. Персональные сценарии не читались и не изменялись.
- Проверен текущий web/relay-контур и его регрессии; отдельный аудит Apple-клиентов, CloudKit и инфраструктуры не проводился.

## Повторение проверок

```sh
npm run lint
npm run typecheck
npm run build
npm test
npm run test:e2e
npx playwright install webkit
npx playwright test --config playwright.audit.config.ts
npm run staging:check
```

Chromium/WebKit запускаются в отдельных автоматически созданных контекстах. При ручной проверке заставки можно открыть `http://127.0.0.1:5173/__audit__/intro.html` в отдельной вкладке dev-сервера; эта диагностическая страница удерживает финальный кадр. Основной маршрут `/studio` закрывает заставку штатно. Публикация этого dev-сервера наружу не выполнялась.
