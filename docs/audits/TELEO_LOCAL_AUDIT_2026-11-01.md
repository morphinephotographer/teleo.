# Локальная проверка Teleo — 1 ноября 2026

Проверен текущий рабочий каталог с исправлением верхней панели iPad. Публичный сайт не изменялся. Все сценарии использовали отдельные тестовые профили и локальные данные.

## Успешные проверки

- `npm run typecheck`: web, relay, staging, production и production-тесты.
- `npm run lint`.
- `npm test`: 19 файлов, 189 тестов.
- `npm run build`.
- `npm run production:check`: production-сборка и Cloudflare dry-run, без публикации.
- `npm run apple:test`: 14 XCTest-тестов (11 Core, 3 Transport).
- Xcode: сборки Teleo-iOS для iOS Simulator и Teleo-macOS, без подписи.
- Дополнительная проверка iPad в WebKit: 24 сочетания (en/uk/ru × light/dark × 1390×970, 970×1390, 820×1180, 1180×820). Системный отступ сверху смоделирован как 24 CSS px; проверены границы и отсутствие пересечений верхних элементов, положение области чтения и отсутствие pageerror. Скриншоты 1390×970 и 970×1390 просмотрены визуально.
- Production-сборка офлайн в Chromium, WebKit и Firefox: сохранение Unicode-текста, перезагрузка без сети, переключение языка и повторная перезагрузка.

## Общий браузерный прогон

Проверены 12 наборов в Chromium, WebKit и Firefox: **210 проверок, 132 прошли, 78 завершились ошибкой, пропусков нет**. Это 26 различных сценариев со сбоями в каждом из трёх движков. По журналам они останавливаются на старых селекторах, устаревших координатах или отсутствующих эталонных изображениях.

Первичный прогон с таймаутом 45 секунд подтвердил повторяющиеся ожидания удалённых элементов и был остановлен. Затем все 210 проверок выполнены заново: обычный таймаут 45 секунд, для четырёх исторических наборов — 8 секунд после диагностики. Явные таймауты внутри тестов сохранены. ## Проблемы автоматических браузерных проверок

Часть исторических сценариев не соответствует текущему интерфейсу. Эти сбои сами по себе не доказывают ошибку приложения; они означают, что соответствующие ветки сценария не завершили проверку поведения.

- `tests/e2e/reader-v12.spec.ts`: старые селекторы `.reader-dock`, `.speed-group output`, `.dock-inline-panel`; текущий интерфейс использует `.approved-reader-toolbar` и `.mobile-reader-dock`.
- `tests/e2e/r400.spec.ts`, `tests/e2e/helpers.ts`: закрытие Settings ожидает удалённую кнопку Close; далее сценарии используют старую панель чтения. Современные проверки профилей standard/r400/custom в `library-panel.spec.ts` проверяют текущие действия клавиш отдельно.
- `tests/e2e/welcome.spec.ts`: язык ищется в header, а не в Settings; восстановление Welcome ожидается в старом блоке Getting started. Текущие проверки в `reading-polish.spec.ts` проверяют локализацию, сохранение правок и восстановление отдельно.
- `tests/e2e/full-audit.spec.ts`: адаптивный сценарий пытается измерить скрытый `header .language-control` и получает null вместо прямоугольника.
- `tests/e2e/approval-v3.spec.ts`: сравнение положения кнопки пульта с устаревшим y=15 вместо текущего y=13 на широком desktop; старые всплывающие настройки темы вместо прямого переключения; отсутствующий `docs/screenshots/approval-v3-before-<engine>-phone.png` для визуального сравнения.

## Границы проверки

Реальная строка состояния iPadOS, физическая клавиатура/пульт, касания на устройстве и установка PWA на физическом iPad не проверялись. WebKit и моделирование safe area подтверждают вёрстку в тестовом окружении, но не заменяют проверку устройства. Проверка не является доказательством отсутствия всех возможных ошибок.
